## Технологический выбор (и почему он и есть «применённая наработка»)
Главный вывод исследования: для Яндекса выигрывает **серверный/статический HTML с нулём лишнего JS**, а не SPA. Поэтому стек здесь — **статический сайт без сборки и без рантайм-JS**: YATI читает готовый DOM при первом обходе, нет риска склейки пустых оболочек, TTFB минимальный. Это не «упрощение», а прямое следствие механики (SPA без SSR отдаёт краулеру пустой `#app` → дубли).
- Системный стек шрифтов (ноль внешних запросов, быстрый первый экран).
- Нативный `loading`/адаптив, inline-SVG-логотип (без растровых запросов).
- Хостинг: GitHub Pages (репозиторий вида `<user>.github.io` → корневой URL, лучше для SEO, чем подпапка).

## Чего намеренно НЕТ (и почему)
- **Партнёрских/реферальных ссылок** — по условию задачи и чтобы не быть дорвеем.
- **Фейковых отзывов пользователей** с именами и «вывел 50 000 ₽» — это фильтр за спам в микроразметке/фабрикацию; рейтинг подан как редакционная оценка по критериям.
- **`meta keywords`, hreflang** (одноязычный сайт) — эталон: пустая трата.
- **Рантайм-JS-фреймворка** — для этой задачи это риск индексации без выгоды.
